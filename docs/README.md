# 프로젝트 문서 규칙

프로젝트의 계획, 데이터베이스 SQL, 개발 기록은 `docs` 아래에서 관리한다.

## 디렉터리

- `plans/`: 전체 개발 및 변경 계획
- `sql/`: Supabase 테이블, 인덱스, 함수, RLS 정책 생성 SQL
- `logs/`: 일자별 실제 개발 내용과 검증 결과

## 파일명

- 계획: `PLAN_계획내용.md`
- 개발 로그: `DEV_YYYYMMDD.md`
- SQL: 적용 순서를 나타내는 번호와 내용을 사용한다. 예: `001_auth_profiles_scores.sql`

## 기록 원칙

- 계획 문서에는 목표, 범위, 단계, 완료 조건, 위험 요소를 기록한다.
- SQL 파일에는 반복 실행 가능 여부와 적용 전제조건을 주석으로 남긴다.
- 개발 로그에는 계획이 아니라 해당 날짜에 실제로 수행한 변경, 검증, 미완료 작업을 기록한다.
- 같은 날짜의 작업은 새 로그를 만들지 않고 해당 날짜 파일에 이어서 기록한다.
- 환경변수의 실제 값과 Supabase secret key는 어떤 문서에도 기록하지 않는다.
