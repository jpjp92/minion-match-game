# 2026-08-20 개발 로그

## 배경

배포 환경(`https://minions-match.vercel.app`)에서 시작 화면이 `Preparing Minions...` 상태로 멈추고 게임 시작 버튼이 계속 비활성화되었다.
브라우저 콘솔: `GET /api/images 503 (Service Unavailable)` → `Error fetching images from private Storage: Image API returned HTTP 503`.

## 원인

1. `App.tsx`는 `imagePool.length > 0`일 때만 `isReady`를 켠다. `/api/images`가 실패하면 `fetchAvailableImages()`가 빈 배열을 반환하므로 시작 화면이 영구적으로 로딩 문구에 머문다(재시도 UI도 없었다).
2. 기존 `/api/images`는 503을 두 곳에서 반환했고 응답 본문이 동일 계열이라 원인을 구분할 수 없었다.
   - 익명 로그인 실패: `auth.signInAnonymously()` 오류(Anonymous Sign-Ins 비활성화, 익명 로그인 rate limit 초과 등)
   - `game-images` bucket에 이미지가 없음
3. 익명 로그인은 이 엔드포인트에서 인가에 사용되지 않았다. 목록 조회와 signed URL 발급은 모두 admin client(RLS 우회)가 수행하므로, 익명 로그인은 실질적인 보안 효과 없이 단일 실패 지점으로만 동작했다. 또한 요청마다 새 익명 사용자가 생성될 수 있어 Vercel 공용 egress IP 기준 익명 로그인 rate limit에 쉽게 도달한다.

## 변경 내용

- `app/api/images/route.ts`
  - 익명 로그인 게이트 제거(인가에 사용되지 않던 실패 지점 제거).
  - Storage 목록 조회를 페이지네이션 처리하고 이미지 확장자만 필터링.
  - Storage 오류·빈 bucket·signed URL 없음인 경우 503 대신 `public/images` 로컬 이미지로 폴백(200, `source: "local"`, `reason: "<원인>"`).
  - 폴백 목록까지 비어 있을 때만 503을 반환하고 `reason`을 함께 노출.
- `lib/game/localImages.ts` 추가: `public/images`와 짝을 맞춘 폴백 목록(서버리스 번들에 `public/`이 포함되지 않으므로 상수로 관리).
- `utils/gameUtils.ts`: 응답의 `reason`을 콘솔 오류에 포함하고, 폴백 사용 시 경고 로그를 남긴다.
- `App.tsx`, `components/StartScreen.tsx`: 이미지 로딩 실패 시 안내 문구와 `다시 시도` 버튼을 노출한다(무한 `Preparing Minions...` 제거).

## 검증

- `npm run typecheck`, `npm run build` 통과.
- `npm test` 23건 통과(`StartScreen` 실패 상태·재시도 테스트 추가).
- Supabase 환경변수 없이 `next start` 후 `GET /api/images` → 200, `source: "local"`, `reason: "storage_error: Supabase admin environment variables are not configured"`, 로컬 이미지 26개 반환. `/images/2.jpg` → 200.

## 남은 작업

- 배포 로그(`[GET /api/images] falling back to local images (...)`)의 `reason`으로 실제 원인을 확정한다.
  - `storage_bucket_empty` → 운영 Supabase 프로젝트에 `node scripts/upload-game-images.mjs` 실행 필요.
  - `storage_error: ...` → `SUPABASE_URL` / `SUPABASE_SECRET_KEY` 및 bucket 존재 여부 확인 필요.
- private Storage 정책을 엄격히 유지하려면 `public/images`를 저장소에서 제거해야 하지만, 그 경우 로컬 폴백도 함께 사라진다. 정책 결정 필요.

## 추가 이슈: 게임 종료 후 버튼 무한 로딩

### 원인

`components/ResultModal.tsx`의 `Play Again` / `Hall of Fame` / `Back to Menu` 세 버튼이 모두 `disabled={saveStatus === 'saving'}`였다.
`App.tsx`의 `saveToLeaderboard()`는 `POST /api/scores`에 타임아웃이 없었기 때문에, 응답이 늦거나 매달리면 모달 전체가 잠긴 채로 남아 무한 로딩처럼 보였다.
실제 응답은 실패였고(`Cloud save failed. Record kept locally.`), 점수 저장은 익명 로그인(`auth.signInAnonymously()`)에 의존하므로 `/api/images`와 동일한 계열의 실패로 추정된다.
기존 클라이언트 로그는 `HTTP <status>`만 남겨 실패 단계를 알 수 없었다.

### 변경 내용

- `components/ResultModal.tsx`: 저장 상태로 버튼을 막지 않는다. 저장은 백그라운드로 계속되고 상태 문구만 갱신한다.
- `lib/http.ts` 추가: `fetchWithTimeout`(기본 10초). `/api/images`, `GET /api/scores`, `POST /api/scores` 호출에 적용해 응답 없는 요청이 UI를 잠그지 못하게 한다.
- `App.tsx`: 저장 실패 시 서버 응답의 `reason`·`error`를 콘솔 로그에 포함. 저장 중 다른 판으로 이동한 경우(`savedScoreKeyRef` 불일치) 지난 판의 저장 결과 문구로 새 판 상태를 덮어쓰지 않는다.
- `lib/apiError.ts` 추가(`StageError`): 실패 단계를 짧은 코드로만 응답에 노출하고 상세 원인은 서버 로그에 남긴다.
  - `/api/scores`: `anonymous_auth_failed`, `profile_upsert_failed`, `score_insert_failed`, `scores_query_failed`, `profiles_query_failed`, `supabase_server_env_missing`
  - `/api/images`: `storage_bucket_empty`, `storage_list_failed`, `signed_url_failed`, `signed_url_empty`, `supabase_admin_env_missing`
  - 이전 커밋에서 이미지 응답에 담았던 Supabase 원본 오류 메시지는 코드로 대체했다.

### 검증

- `npm run typecheck`, `npm run build` 통과, `npm test` 27건 통과(`lib/http.test.ts` 신규, `ResultModal` 저장 중 이동 허용 테스트로 교체).
- 환경변수 없이 `next start` 후: `POST /api/scores` → `{"reason":"supabase_server_env_missing"}`, `GET /api/images` → `source: local`, `reason: supabase_admin_env_missing`.

### 남은 작업

- 배포 로그에서 `POST /api/scores`의 `reason`을 확인한다. `anonymous_auth_failed`면 Supabase **Authentication → Providers → Anonymous** 활성화 여부와 익명 로그인 rate limit을, `profile_upsert_failed` / `score_insert_failed`면 `001_auth_profiles_scores.sql`의 RLS 정책 적용 여부를 점검한다.
